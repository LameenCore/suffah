# Accessibility pass — 2026-09-06 (T60)

Target: WCAG 2.2 AA. This is the audit + the fixes that could be made without a
screen reader; the manual passes that still need a human are listed at the end.

## Fixes applied

### Structure & keyboard
- **Skip link** (`components/SkipLink.tsx`) is the first focusable element in
  `DashboardChrome`; `<main id="main" tabIndex={-1}>` is its target on every
  dashboard, and on the public landing + `/for-masjids`.
- **Landmarks**: `<nav aria-label>` on the sidebar nav; one `<main>` per page.
- **Mobile drawer** (`components/Sidebar.tsx`): now `role="dialog"` +
  `aria-modal="true"` + an accessible name; **focus is trapped** inside it while
  open, **Escape closes it**, `document.body` scroll is locked, and focus
  **returns to the Menu trigger** on close. The trigger carries
  `aria-expanded` / `aria-haspopup="dialog"`.
- Global `:focus-visible` ring already existed (kept).

### Motion
- `@media (prefers-reduced-motion: reduce)` in `globals.css` collapses every
  transition/animation to ~instant and stops the decorative `.wf-stream` ledger
  animation and any keyframe loops.

### Forms & status
- Label associations fixed where a `<label>` was a bare sibling of its control
  (`components/admin/PodCard.tsx`, `components/admin/VolunteerManager.tsx`) —
  the control now sits inside its `<label>`.
- Form/submit error messages get `role="alert"` (`/login`, `/signup`,
  `/for-masjids`; the pod-board + moderation error text already had it).
- `OfflineIndicator` is a `role="status"` `aria-live="polite"` region and no
  longer causes a hydration mismatch (uses `useSyncExternalStore` with an
  always-online server snapshot).

### Contrast (both themes)
- `--ink-4` (faint captions) was **2.5:1** on the page background — a clear AA
  fail. Retuned:
  - light: `#a99a86` → `#7a6b55` (4.7:1 on bg, 5.1 on surface, 4.5 on surface-2)
  - dark: `#8a7c69` → `#9a8c76` (5.4:1 on bg, 4.9 on surface)
  Everything else in the palette (`--ink-3` / `--ink-2` / `--ink`, the brand and
  semantic ramps on their soft backgrounds) was spot-checked and already ≥ AA for
  its text size.

### Automated gate
- `npm run check:a11y` (`scripts/check-a11y.ts`): runs **axe-core** over the
  rendered HTML of `/login`, `/for-masjids`, `/student`, `/parent`, `/admin`,
  `/admin/compliance` in jsdom and fails on any `serious` / `critical` violation.
  Wired into `.github/workflows/ci.yml` after the test step. Current result:
  **no serious/critical violations.**
- `eslint.config.mjs`: the `jsx-a11y` rules that catch real defects (alt text,
  anchor/button content, aria props & roles, label association, redundant roles)
  are now **errors**, not warnings — a regression fails the build.

## Still needs a human (pre-launch)

axe in jsdom has no layout engine and cannot replace a real assistive-tech pass.
Before a public launch:

1. **Screen-reader pass** (NVDA on Windows, VoiceOver on macOS/iOS) through each
   of the five demo screens **and** the core student loop (lesson → mark
   complete → checkpoint → result). Verify: headings read in order, the skip link
   works, form fields announce their label + error, async results (checkpoint
   pass/fail, briefing generation, sync status) are announced, the mobile drawer
   traps and restores focus, tables have usable headers.
2. **Keyboard-only walk** of every flow end to end — no focus traps outside the
   drawer, visible focus on every interactive element including custom
   `<div role="button">`-style controls, logical tab order.
3. **Contrast** of any *non-token* colour (inline `text-[color:...]`, chart
   strokes, badge text on tinted fills) with a real contrast tool at the actual
   rendered size.
4. **Zoom to 200%** and **reflow at 320px** — mostly covered by T62 but re-check
   with the a11y hat on (no loss of content or function).
5. A skip link on the short public pages (`/login`, legal pages) — currently only
   the dashboards and the two long marketing pages have one.
