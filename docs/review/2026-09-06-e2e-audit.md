## Bugs found and fixed

### 1. Hydration mismatch on every student lesson page — FIXED (`ffd78e0`)
`components/student/OfflineIndicator.tsx` seeded its state with
`typeof navigator === "undefined" ? true : navigator.onLine`. **Node 21+ defines
a global `navigator`** (without `onLine`), so on the server this evaluated to
`undefined` → the component rendered its status pill during SSR but `null` on the
client → React #418 on `/student/[courseId]`. Fixed with a `mounted` guard
(render nothing until the client effect runs). Also tightened the two
`navigator.onLine` checks in `Checkpoint.tsx` to `=== false`.

### 2. Append-only triggers blocked tenant/student cascade deletes — FIXED (`9c18ff1`, migration `0022`)
`audit_log` / `consent_records` / `model_call_log` each had a
`BEFORE UPDATE OR DELETE` trigger rejecting **every** DELETE, including the
cascade from removing a masjid or a student. A masjid with any audit row could
never be deleted — breaking `provisionMasjid()`'s rollback (T33) and the Law 25
right-to-erasure path (T36), and leaving test tenants stuck. `0022` allows a
DELETE only when the parent (masjid, or for `consent_records` also the student)
is already gone — a genuine cascade — while a direct DELETE against a live tenant
and any UPDATE stay rejected. Verified: cascade delete works, direct
`DELETE FROM audit_log` still blocked. Also removed a leftover "T63 Test Masjid"
tenant from the live DB.
