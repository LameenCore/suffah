# Codebase audit - 2026-09-05

Applied `.claude/skills/{security-review, api-design, app-verification}` and an
edge-case sweep across `lib/`, `app/`, `components/`, `scripts/` (~10.8k LOC).

## Summary

The code is defensively written throughout: `searchParams` are `typeof x ===
"string"` guarded, every division has a zero guard, embedded-relation reads are
null-safe, AI calls fall back to hand-authored content, and cross-tenant ids
resolve to `null`/first-in-masjid rather than leaking. One real tenant-isolation
gap was found and fixed; the rest are defense-in-depth notes.

## Findings

### 1. FIXED - `markReportExported` had no tenant check (security)

`lib/compliance/report.ts` / `app/admin/compliance/actions.ts`. The Server
Action `markExportedAction(reportId)` flipped `compliance_reports.exported` by id
with no masjid scoping - any authenticated admin could mark any masjid's report
exported by supplying its UUID. Low impact (a boolean, no disclosure) but a
tenant-isolation break. Fixed: `markReportExported(reportId, masjidId)` now
verifies the report's student belongs to the caller's masjid first.
Commit: security-review fixes.

### 2. FIXED - `getLatestStoredReport` not masjid-scoped (defense in depth)

Same file. Read `compliance_reports` by `student_user_id` with no masjid check.
Not exploitable today (the page selects the student from a masjid-filtered list
and a foreign `?student=` id falls back to the first in-masjid student), but the
helper should stand on its own. Now takes `masjidId` and returns `null` for a
cross-tenant student.

### 3. FIXED - PostgREST `.or()` filter string interpolation (hardening)

`lib/db/barakah-queries.ts` `getChildBarakahSummary` built
`student_user_id.eq.${id},pod_id.eq.${id}` by string concatenation. Both ids are
session/DB UUIDs (not free text), so not exploitable, but a string-built filter
must never take an unvalidated value. Added `assertUuid()` on both before the
splice. This is the only `.or()` / string-built filter in the codebase.

### 4. NOTED - helpers without a `masjidId` param (not exploitable)

`getLatestTermExamResult`, `saveTermExamResult` (`lib/db/exam-queries.ts`),
`tryAddSystemNote` (`lib/db/continuity-queries.ts`). All current call paths scope
upstream - the course is validated via `getCourseForMasjid` before these run,
`studentUserId` is always the session user, and `tryAddSystemNote`'s `podId`
comes from the student's own pod lookup. Left as-is to avoid churn in files an
adjacent session is editing; a future caller must not pass an unvalidated id to
them.

### 5. NOTED - concurrent "Incorporate contributions" (race, demo-benign)

`lib/ai/lesson-revision.ts` reads pending contributions, appends, then marks them
incorporated - two concurrent calls could double-append and double-bump the
version. Single-user demo; not worth a lock. A `WHERE incorporated = false`
guard on the update already prevents re-marking.

### 6. NOTED - date formatters assume valid ISO

~10 components call `new Date(dbValue).toLocaleDateString(...)` directly. DB
columns are `timestamptz NOT NULL`, so this is safe in practice; a stray
null/undefined would render "Invalid Date" (not a crash). A shared safe formatter
would be tidier but is cosmetic.

## api-design pass

Route handlers and Server Actions checked against the skill's checklist:

- Tenant scoping from the session: PASS (every `lib/db/*-queries.ts` helper takes
  `masjidId` first and checks it; routes pass `user.masjidId`).
- Handler/action auth: PASS (every route re-resolves the session; every
  `actions.ts` has a `requireAdmin()`/`requireStudent()` first line).
- AI output persisted before return, `force` respected, fallback on failure:
  PASS (`lib/ai/*` + `lib/ai/fallback-*`).
- Body parsing guarded, inputs validated, enums whitelisted: PASS for the
  generation routes; Server Actions validate presence + enum but do not cap
  free-text length (`note`, `certification_note`). Acceptable under dev-cookie
  auth; add `.slice(0, N)` before insert if this ships.
- Error text / logs: generation routes echo `err.message` from our own
  `throw new Error("fnName: ...")` helpers - these say "X not found in this
  masjid", never a student name, so within tolerance. No `console.error` prints
  PII.
- Response shapes: consistent across sibling routes.
